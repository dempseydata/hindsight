# ADR-0007: Direction — V3 · Indigo deck; tokens.css is the contract

**Date:** 2026-08-24 · **Status:** accepted · **Decides:** the design direction chosen in [Diverge #34](../../background/tickets/034-diverge-five-candidate-directions.md) → [Narrow #35](../../background/tickets/035-narrow-one-direction-three-variants-one-winner.md)

## Context

Direction was chosen comparatively, not in one shot: five candidate directions side by side, then three variants of the winner, identical real content from `local-data/hindsight.db` in every comp — comparative judgement over absolute, per my-process's Design flow. Reference artboard: `VariantIndigo.dc.html` on the "Hindsight Narrow" canvas.

## Decision

- **Family:** observability workhorse (Grafana/Honeycomb lineage) — titled panels, stat tiles, shared 30-day axis, blue/red thresholds — with one graft from the terminal-instrument family: **bar sparklines**, not heat strips.
- **Look:** near-black indigo ground, elevated 6px-radius panels, periwinkle accent, 28px stat numerals, system-ui + ui-monospace, 200ms ease hover lift.
- **Spark grammar (standard):** per-day bars on the shared 30-calendar-day axis, own peak per spark, missing day = gap, never zero.
- **Assets:** judged — none needed; no imagery surface exists in this direction.
- **`design/tokens.css` is the direction contract:** committed, inlined by the server into every page at render time, never forked. Values verified verbatim against the winning artboard on 2026-08-20. Comps are reference only; artboard markup is never imported.

## Consequences

- The reference canvases ("Hindsight Diverge", "Hindsight Narrow") are **unwatched** since 2026-08-21 — the live artifact watches died and cannot be re-armed from a build session. Any later canvas edit therefore requires re-verifying `tokens.css` verbatim against `VariantIndigo.dc.html` before it influences the repo.
- The floor rules ride in `tokens.css`'s header comment (every colour via named tokens, semantic text in `-text` weights, red pairs with blue, accent never on body text or large surfaces, chart data ink on its own palette).
- No asset-production step exists in the build.

## Addendum (2026-08-25, ticket #52)

A **derived product `DESIGN.md`** now lives at the repo root, generated by Impeccable's documenter from the shipped, audited UI (post-#47), with its `design.json` sidecar under `.impeccable/`. It exists because Impeccable's live hooks and audit only run their design-system drift detection (undocumented colours, undeclared faces, off-scale radii) against a `DESIGN.md` — the house standard's "keep a product copy if tooling needs one" clause, satisfied by derivation rather than sync since the house v1.2 document is not followed here.

Authority is unchanged: **`tokens.css` remains the sole direction contract**; on any conflict `tokens.css` wins. `DESIGN.md` is re-derived (documenter re-run) whenever `tokens.css` or the UI's visual system changes — it is never hand-edited into a second source of truth.

## Amendment (2026-08-28, ticket #71): stage identity palette

The how-view keys each declared stage to a hue, on the stated-process card and the phase-run band's left rule, so a run is placed against its stage at a glance. The contract had no categorical palette to lend it: the ink ramp is sequential and four steps short of five stages, and accent/compare/semantic tokens may not carry identity. `tokens.css` therefore gains a **stage** group — `--o-stage-1..5` (teal, violet, magenta, orange, gold; each ≥6.5:1 on `--o-panel`) plus `--o-stage-off` (the unbucketed grey) — with three rules:

- Stage hues are **non-text marks only** (rules, dots): labels stay `--o-text`, so no `-text` weight is needed.
- Stage hues never colour chart data and never stand in for ok/caution/problem; the reverse also holds — ink and semantic tokens never key a stage.
- Assignment is positional: a declaration's stages take `-1..-5` in declared order and cycle past five. Identity is per project, not per stage name.

The current run's accent rule is replaced by a small `now` badge so the rule can carry the stage. `DESIGN.md` and its sidecar are re-derived accordingly.
